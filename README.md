# MultiThreadDownloader (fast-downloader)

Простой многопоточный загрузчик файлов под **.NET Framework 2.0**, написанный строго на
конструкциях **C# 2.0** (без `var`, LINQ, `async/await`, лямбд — только `Thread`,
`HttpWebRequest`, `lock`). Запускается даже на старых Windows с установленным .NET 2.0.

## Возможности

- Скачивание файла в **несколько потоков (максимум 32)** через HTTP `Range`-запросы.
- **Адаптивный режим** (включён по умолчанию): старт с 2 потоков, замер суммарной
  скорости каждые 1.5 сек. Пока скорость растёт (прирост > 5%) — добавляется по одному
  потоку. Если скорость **перестала расти 2 замера подряд** — потоки больше не
  добавляются, файл докачивается на текущем числе.
- Если сервер не поддерживает `Range` или размер неизвестен — тихое скачивание в 1 поток.
- Простой WinForms UI: поле URL, выбор файла, прогресс текущей загрузки
  (проценты, скорость, число потоков, очередь блоков), **история загрузок**
  (дата, файл, размер, статус, URL), хранится в `history.csv` рядом с exe.
- Ручной режим: снимите галочку «Авторежим» — будет сразу N потоков.

## Требования

### Для запуска готовой программы

- Windows XP SP3 / Vista / 7 / 8 / 10 / 11 (x86 или x64).
- Установленный **.NET Framework 2.0 или новее**.
  На Windows 10/11 включается так: *Панель управления → Программы → Включение или
  отключение компонентов Windows → .NET Framework 3.5 (включает 2.0 и 3.0)*.
- Интернет-соединение. Установка программы не нужна — это один exe-файл.

### Для компиляции из исходников (локально)

- Windows (10/11, x64).
- **.NET SDK 8 или новее** — скачать с https://dotnet.microsoft.com/download
  (проверить: `dotnet --version`).
- **Git** — https://git-scm.com/download/win (проверить: `git --version`).
- Доступ в интернет при первой сборке (скачивается пакет
  `Microsoft.NETFramework.ReferenceAssemblies` для таргета `net20`).

### Для компиляции в облаке GitHub

Ничего ставить не нужно — достаточно аккаунта GitHub и этого репозитория.
Сборка выполняется workflow `.github/workflows/build.yml` на `windows-latest`.

## Установка

### Вариант A — скачать готовый exe (рекомендуется)

1. Откройте репозиторий на GitHub → вкладка **Actions**.
2. Выберите последний успешный запуск **build** (зелёная галочка).
3. Внизу страницы скачайте артефакт **MultiThreadDownloader-net20** (или zip).
4. Распакуйте в любую папку и запустите `MultiThreadDownloader.exe`.

### Вариант B — собрать локально из исходников

```powershell
# 1. Склонировать репозиторий
git clone https://github.com/modyle/fast-downloader.git
cd fast-downloader

# 2. Собрать Release
dotnet build MultiThreadDownloader.sln -c Release
```

Готовый файл:

```text
src\MultiThreadDownloader\bin\Release\net20\MultiThreadDownloader.exe
```

Скопируйте его на любой компьютер с .NET Framework 2.0+ и запускайте.
Вместе с exe можно положить `history.csv` (создастся сам при первом запуске).

### Вариант C — скомпилировать в облаке GitHub

1. Сделайте fork репозитория (или запушьте код в свой — см. ниже).
2. Любой `push` в ветки `main`/`master` (а также Pull Request) автоматически
   запускает workflow **build**.
3. После завершения заберите exe из артефактов запуска, как в варианте A.

```powershell
# Как запушить свои изменения:
git add -A
git commit -m "Мои изменения"
git push origin main
```

## Использование

1. Запустите `MultiThreadDownloader.exe`.
2. Вставьте **URL файла** в верхнее поле.
3. Укажите, **куда сохранить** (кнопка `...` или впишите путь вручную;
   если оставить пустым — программа сама предложит имя из URL).
4. Выберите **макс. потоков (1–32)** и при желании оставьте включённым
   **авторежим** (рекомендуется).
5. Нажмите **«Скачать»**. Внизу видны: прогресс в процентах, объём
   «скачано из всего», текущая скорость, число живых потоков и очередь блоков.
   Если скорость перестала расти — в строке потоков появится
   пометка «рост остановлен».
6. Кнопка **«Стоп»** прерывает загрузку (запись попадёт в историю как «Отмена»).
7. Завершённые/прерванные загрузки появляются в таблице **«История загрузок»**.
   Кнопки под ней: **«Очистить историю»**, **«Открыть папку загрузок»**.

## Как работает адаптивный режим

1. Файл делится на блоки (минимум 256 КБ, всего не более ~512 блоков).
2. Создаётся файл нужного размера, блоки раздаются потокам через общую очередь.
3. Старт с 2 потоков. Каждые 1.5 сек контроллер сравнивает текущую скорость
   с лучшей: прирост > 5% — плюс один поток (до лимита 32);
   два замера подряд без прироста — новые потоки больше не создаются.
4. Каждый блок качается отдельным `Range`-запросом и пишется на своё смещение.
   Неудавшийся блок возвращается в очередь (до 5 попыток).
5. Файлы меньше 1 МБ, без `Accept-Ranges: bytes`, с неизвестным размером
   или больше 2 ГБ качаются в один поток (ограничение `AddRange` в .NET 2.0;
   на рантайме .NET 4.x long-диапазоны подхватываются через рефлексию).

## Ограничения (честно)

- «.NET Framework 2.5» не существует — проект таргетит **.NET 2.0**
  (результат тот же: работает на старом рантайме, язык ограничен C# 2.0).
- Старый `HttpWebRequest` на очень старых ОС может не договориться по TLS 1.2
  с некоторыми https-сайтами (в коде пробуем включить TLS 1.1/1.2 числовым кастом,
  но на Windows XP без обновлений часть сайтов не откроется — это ограничение
  платформы, а не баг).
- Многопоточность ускоряет, только если сервер отдаёт `Accept-Ranges: bytes`
  и не режет скорость на соединение. Иначе — честный однопоток.
